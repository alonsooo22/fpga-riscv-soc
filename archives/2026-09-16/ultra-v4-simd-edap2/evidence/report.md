# SIMD 完整程序利用率与后续方向

2026-09-15，决策代理直接执行。结论：保留四指令全开硬件与 EDAP2 软件为隔离候选；完整算法16迭代约3.3340 CM/MHz，较原C短测速度提高8.072%。一次已有路由checkpoint的物理优化后80MHz内部setup/hold通过。没有修改accepted D1/v4、SIMD功能RTL，也没有运行516迭代或宣称正式CoreMark成绩。

## 实际执行与口径

- 软件复制自compiler_screen_20260915/source/coremark-ultra。只替换实验副本core_matrix.c，保留原初始化、算法顺序、CRC、seeds、TOTAL_DATA_SIZE=2000和签名接口。
- xPack GCC15.2，原C选项-O3 -flto -funroll-loops、rv32im_zicsr/ilp32；新增-g供源码归属，所有候选实测即使用该ELF，无换镜像profile。custom由.insn生成，不是编译器自动识别SIMD。
- 16次迭代；C参考5186392cycles复用历史short_C，不拿516次结果直接比较。E使用现有E RTL模型，其余使用现有ALL模型；持久ultra-top-tcm-dev，关闭波形，不重新生成RTL模型。
- E只替换位提取。EDAP增加N=9专门化、每调用重新生成288B A行/B转置列pair缓冲、DOT和ADD16。N!=9保留普通矩阵fallback。
- EDAP2只增加一个双输出累加软件候选。SP2是归因对照：同EDAP2循环/布局，所有intrinsic改为C标量语义，反汇编确认无custom指令。SP2不是额外硬件配置或另一轮搜索。
- 所有预打包均发生在原CoreMark计时区间内，未缓存可变输入跨调用。所有四个新软件均正常退出，五项CRC等于同工作量参考：e9f5/e714/1fd7/8e3a/dd50。
- 原打印的编译flags字符串未自动包含LTO、unroll等完整信息；实际编译命令以各build/build.log和manifest.json为准。源码修改版均标为扩展实验，不能标称未改原算法源码的标准成绩。

## 分块为什么收益很小

| 普通矩阵，ROI合计 | EDAP | EDAP2 |
|---|---:|---:|
| 驻留周期 | 16160 | 15720 |
| retired | 12896 | 12896 |
| load / store | 4368 / 1600 | 4368 / 1600 |
| 栈区访存 | 2872 | 2872 |
| scoreboard周期 | 2520 | 2296 |
| MUL等待标记 | 1152 | 1008 |

优化只改善局部依赖顺序，未减少访存。编译器原本已对固定N=9展开/复用；源代码写成双输出不等于机器码只保留两个活跃输出。两份最终.text同为36944B。

反汇编仍在计算循环中反复出现lw ...offset(sp)，例如EDAP2 0x48d4、0x48e8、0x4920等PC各退休72次；不是仅入口/出口保存寄存器。当前有寄存器压力和重载，不能称调度最优，也不能声称没有spill。2872是整个普通矩阵归属下的栈访问总数，不全部等于可消除spill。

下一次若继续软件优化，优先限制j方向过度展开、保留k方向4对展开，缩短活跃值生命周期。收益需与新增循环控制比较，不继续扩大分块；本轮未另开这一候选。

ROI观察到的最小sp访存基址0xfda0，远离signature结束0xf000；仅代表有界窗口观察，不是完整程序栈高水位证明。静态__bss_end=0xc578，signature=0xe000..0xf000，stack_top=0x10000，链接检查通过。

## 剩余热点与架构判断

EDAP2：状态190703周期（31.80%），链表198393（33.08%），CRC81768（13.64%），矩阵128728（21.47%）。普通矩阵只剩15720（2.62%），bitextract70968（11.83%），mul_vect4802（0.80%），mul_const4332（0.72%），add_const3290（0.55%），matrix_sum29456（4.91%）。

1. **现有SIMD仍可覆盖matrix_mul_vect。** 每输出4对DOT＋1标量尾部，B向量可在调用内复用。该热点全部消除也只影响约0.8%的当前周期，优先级低于控制现有栈重载；还须计入A/B打包。
2. **bitextract的XBEXTU替换已经全覆盖当前两个位段模式。** load11664、MUL11664、XBEXTU11664仍是主要运算链；scoreboard8424，其中load/MUL标记4536/3240。相对旧画像减指令后等待增加，说明依赖距离和调度需要关注，不能把更大stall直接当功能回归。
3. **现有DOT可尝试在提取后组合，但无明显指令数优势。** 两个元素保留两次第一乘法、四次BEXT；再两次PACK和一条DOT替换第二层两次MUL及求和。忽略地址/循环时，原两元素约14条load/运算指令，改后仍约14条；增加活跃寄存器。这里只是静态成本模型，未宣称收益，不再盲目实现。
4. **mul_const要求两个独立32位输出，DOT不能替代。** ADD16只给截断半字，不能保留这里的宽化结果。宽化寄存器/小型向量执行更自然，但热点不足1%，不能单独支撑大资源投入。
5. **matrix_sum不是普通归约。** 阈值清零和prev形成跨元素状态，需保留语义，不能直接换向量sum。
6. **链表/状态/CRC不是切到vector就解决的部分。** 指针地址链、状态递推及CRC递推仍存在；它们合计约78.5%的新程序周期。

后续简易vector的首个合理目标是bitextract的宽化、多步逐元素计算：本地保存多个独立32位中间结果，逐元素提取和第二次乘法，再累加，并尝试按输出列复用A、连续读B。核心问题是减少标量分发、地址和打包成本，不是机械增加乘法器。只有32位计算通路时，不能假定两个32位结果每拍同时处理。

以当前bitextract 11.83%份额作理想化Amdahl预算：热点整体2倍/4倍加速分别约带来全程序6.29%/9.74%速度提升；尚未计接口、准备、降频。这个范围适合约束小型局部向量状态的预算，不支持为CoreMark直接增加上万LUT的完整RVV。保留矩阵/状态接口，向量结构另做候选，不在本轮集成。

## 物理时序与资源

基于已有simd_subset_v1_routed.dcp，先查询DOT路径，再仅运行一次phys_opt_design -directive AggressiveExplore与route_design；未重新综合、未修改RTL、时钟仍12.5ns、未新增false/multicycle例外。新结果独立保存physical_followup/。

- DOT专项真实路径：E1操作数寄存器→两颗DSP及结果选择→E2结果，data delay9.479ns、slack+2.838ns。旧违例不是DOT计算边界不足，不需要为DOT增加流水级。
- 物理优化对ALU结果网络做pin交换，对恢复地址/LSU控制的局部组合做逻辑变换。全局WNS从-0.091变为+0.013ns、TNS0；WHS+0.052ns、THS0；setup/hold均0违例端点。
- 顶层3939 LUT/1910 FF/6 DSP/16 RAMB36，相对旧候选+1 LUT；相对v4+250 LUT、+2 DSP。DRC0error/45warning，内部未约束端点0、组合环0。OOC外部接口无板级IO delay，仍不称板级验证或实测Fmax。
- 新最差路径仍为TCM→branch_pc D，余量只有13ps。通过这一实现的80MHz STA，不宣称有宽裕时序余量。
- 同80MHz下，EDAP2短测速度提高8.072%、LUT提高6.777%，每LUT吞吐约提高1.213%；DSP单列。数值是短测＋OOC资源的比较，不是最终正式成绩。
